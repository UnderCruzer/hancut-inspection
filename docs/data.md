# 현재 데이터 — 보안검색 X-ray

2026-09-24 범위 전환(#12). 학교 AWS 계정이 `us-east-1` 고정이라 AI Hub 데이터는 국외 반출 합의 없이 쓸 수 없다.
X-ray 보안검색 공개 벤치마크는 반출 제약이 없고 학술 목적 이용이 명시돼 있어 이 계정에서 그대로 쓸 수 있다.

## 받을 대상

**PIDray 만 받는다.** 2026-09-24 실제로 요청해 확인한 결과다.

| 대상 | 경로 | 상태 |
|---|---|---|
| PIDray `pidray.zip` 47,677장 / 12종 / bbox + mask | Google Drive | **11GB, 로그인 없이 받아짐** |
| PIDray 확장판(124,486장) 어노테이션 | Google Drive | 1.06GB |
| PIDray 확장판 **이미지** | Baidu 전용 | 받을 수 없음 |
| SIXray 1,059,231장 | Baidu + KS3 미러 | **미러 정지** |
| Voxel51/PIDray | HuggingFace | 9,482장(easy 일부). 파이프라인 동작 확인용 |

SIXray 의 비Baidu 경로(`aivc.ks3-cn-beijing.ksyun.com`)는 버킷 전체가 다음을 반환한다.

```
<Code>KS3DownloadServiceNotOpened</Code>
<Message>The reason why it can't be used may be due to arrears.</Message>
```

요금 미납으로 정지된 상태다. 한 파일이 아니라 루트까지 전부다. **SIXray 는 현재 Baidu 외에 경로가 없다.**

## 용량

11GB, 압축 해제까지 25GB 를 잡으면 충분하다. AWS 인스턴스 디스크 192GB 이므로 여유롭다.
**용량은 더 이상 이 프로젝트의 제약이 아니다.** 962GB 를 전제한 이전 계획의 축소 논의는 전부 무효다.

## 음성 표본 문제와 그 해결

받을 수 있는 47,677장은 **전부 위해물품이 든 사진**이다("each of which contains at least one prohibited item").
따라서 "위해물품 없는 가방을 몇 % 자동 통과시키나"를 측정할 분모가 없다.

확장판(124,486장)에는 음성이 있다 — IJCV 논문의 R0 노드가 위해물품 포함 여부 이진 분류이고
"otherwise it means just a normal sample"이라고 쓴다. 그러나 그 이미지는 Baidu 에만 있다.
논문 Table 2 는 train 76,913 / easy 24,758 / hard 9,746 / hidden 13,069 만 공개하고 양성·음성 내역은 밝히지 않는다.

**과제 재정의로 푼다(#16).** 품목 단위 이진 정의로 가면 품목 c 를 포함한 가방이 양성,
포함하지 않은 가방이 음성이 되어 품목마다 양성·음성이 모두 생긴다. 놓침은 "품목 c 를 놓침"이다.
위임 정책은 그 위에 얹힌다. SIXray 없이 성립한다.

확장판 이미지는 저자에게 Google Drive 링크를 요청해 볼 수 있다. 성공하면 "가방 단위 자동 통과"로 격상한다.
성공을 전제로 계획을 짜지 않는다.

## 이용 조건

**학술 목적 한정, 상업적 이용 불가, 재배포 금지**다. 국외 반출이나 지역 제한 조항은 **없다**.
EC2 에서 학습하는 것은 학술 이용이고 재배포가 아니므로 `us-east-1` 이어도 무관하다. AI Hub 와 다른 점이 이것이다.

- 원본 이미지와 라벨을 저장소에 넣지 않는다. `.gitignore`의 `/data/`, `ml/data/`, `server/data/` 규칙을 유지한다.
- 논문/발표에 쓸 때 PIDray 원 논문(IJCV 2023)을 인용한다.
- 발표자료에 원본 이미지를 넣을지는 각 저장소의 조건을 다시 확인하고 정한다. 확인 전에는 집계 지표와 직접 만든 도식만 쓴다.

## 왜 이 데이터인가

**난이도 라벨이 붙어 있다.** 시험셋이 easy 9,482 / hard 3,733 / hidden 5,005 로 나뉘어 있다(v1 실측).
easy 와 hidden 은 이미지당 정확히 1종, hard 만 2.08종이다. hard 는 겹쳐서, hidden 은 숨겨서 어렵다.
난이도 라벨은 **시험셋에만** 있다. 학습셋은 `xray_#####.png` 로 구분이 없다.

**인간 기준선이 문헌에 있다.** 판독관 정확도는 최적 조건에서 80~90%다(EU JRC). 인용하는 비교 좌표일 뿐 모델의 입력이 아니다.

## 받은 뒤 확인한 것 (2026-09-27, #14 완료)

`ml/scripts/inspect_dataset.py` 와 `ml/scripts/build_index.py` 가 서로 독립적으로 센 숫자가 일치했다.

| 항목 | 결과 |
|---|---|
| **판본** | **v1, 47,677장.** train 29,457 / easy 9,482 / hard 3,733 / hidden 5,005. 전부 양성, 음성 없음 |
| **장비 메타데이터** | **없다.** `images` 키는 `height`·`width`·`id`·`file_name` 뿐이고 파일명에도 단서가 없다. E4 취소(D12) |
| **난이도 라벨** | 시험셋에만 있다. 학습셋에는 없다 |
| **class_id** | 논문 순서와 완전히 다르다. 1 = Baton, 7 = Gun. `ml/configs/items.json` 에 실측값을 넣었다 |
| **split 누수** | **없다.** 네 split 이 파일명 기준으로 서로 겹치지 않는다 |

### 확인하다 발견한 것

**`images[].id` 는 어노테이션 파일마다 0 부터 다시 시작한다.** train 의 0 번과 easy 의 0 번은 다른 사진이다.
인덱스는 파일명(확장자 제외)을 키로 쓴다.

**맥에서 압축한 부산물이 섞여 있다.** `__MACOSX/` 와 `._*` 파일 5,007개. 세면 이미지가 52,684장으로 잡혀 판본을 오판한다.
조사 스크립트와 로더 둘 다 걸러낸다.

**이미지 크기.** 높이 448 고정, 너비 가변(420·580·620 확인). 컨베이어 라인 스캔 특성이다. 정사각으로 늘이지 않는다.

### 측정 한계

품목별 시험셋 양성이 가장 적은 것은 **Baton 852장**이다. 비율 추정에 10건 이상이 필요하므로 `10/N` 이 실질 하한이고,
Baton 기준 1.17% 다. 주 격자는 **5·2·1%**, 0.5% 는 6종만, 0.1% 는 어느 품목도 불가다(D12).
품목별 수치는 `ml/configs/items.json` 의 `positives` 와 `reliable_min_miss_rate` 에 있다.

### 인덱스

`python3 ml/scripts/build_index.py` 로 만든다. 이미지 × 품목 **572,124행, 26.3MB.**
**커밋하지 않는다.** 어노테이션에서 몇 초 만에 똑같이 재생성되는 파생 파일이라, 커밋하면 재생성할 때마다 저장소가 불어난다.
재현성은 스크립트의 누수 검사와 `items.json` 대조가 보장한다.
