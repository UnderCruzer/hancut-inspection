# 실험 설계

결과물은 앱이 아니라 아래 질문들의 답이다. 일정이 밀리면 E7 → E6 → E5 순으로 줄이고, **E1–E4와 점검 앱은 줄이지 않는다.**

| ID | 질문 | 방법 | 지표 | 우선순위 |
|----|------|------|------|----------|
| E1 | 한 번에 볼 것인가, 나눠서 볼 것인가 | 시설×준수 통합 검출 vs 검출 → 크롭 분류 | 미준수 재현율, 사유 정확도, 추론 시간 | 필수 |
| E2 | 놓침률을 지키며 얼마나 자동화되나 | 놓침률 상한 1·3·5%별 임계값 탐색, 시설별 | 확인 필요 비율, 오경보율 | **필수 · 핵심** |
| E3 | 현장 사진에서도 버티나 | 현장설치 → 현장동영상 이미지 평가, 흐림·어두움·기울기 단계 주입 | 조건별 놓침률 증가폭 | 필수 |
| E4 | 서류 작업이 실제로 줄어드나 | 같은 사람·시설 30건, 종이 점검표 vs 앱, 시나리오 교차 | 건당 소요 시간, 오기재 수 | **필수 · AX 결론** |
| E5 | 점검표 초안은 믿을 만한가 | 판정 결과만으로 초안 50건 → 검수 | 사실 오류, 항목 누락, 수정 비율 | 권장 |
| E6 | 소화기 라벨을 제대로 읽나 | 제조연월 정답 200장 직접 입력 | 일치율, 연한 판정 오류, 판독 실패율 | 권장 |
| E7 | 점검원 정정이 모델을 낫게 하나 | E3 약점 조건의 정정 데이터로 추가 학습 | 정정 건수 대비 놓침률 감소 | 여유 시 |

## 성능 정의 — 교안의 다섯 단계

| 단계 | 이 프로젝트 |
|------|-------------|
| 정의 | 놓침률 상한을 지키며 점검원 확인 비율 최소화 |
| 측정 | 시험 세트로 놓침률·확인 비율 계산 (`ml/hancut/eval/zones.py`), 업무 시간은 앱 로그 |
| 정답지 | 데이터셋 준수/미준수 라벨 + 라벨 200장·초안 50건 직접 |
| 개선 | 모델 구조·입력 크기·임계값을 한 번에 하나씩 |
| 재현 | 시드·서브셋 목록·설정 파일 커밋 |
