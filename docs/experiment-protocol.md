# 실험 수행 규칙

교안의 평가 기준은 "무엇을 만들었나"가 아니라 **"왜 그 방법을 골랐고 성능을 어떻게 점수화했나"**다. 실험을 돌리는 방식이 곧 결과물이므로 규칙을 정해 둔다.

## 다섯 단계

| 단계 | 규칙 |
|------|------|
| 정의 | 무엇을 좋게 만들 것인지 한 문장으로 먼저 적는다. 여기서는 **놓침률 상한을 지키며 확인 필요 비율 최소화** |
| 측정 | 지표 계산 코드를 먼저 만든다 (`ml/hancut/eval/zones.py`). 재지 못하면 좋아진 걸 증명할 수 없다 |
| 정답지 | 어디서 왔는지 기록한다 — 데이터셋 라벨인지, 내가 직접 입력한 것인지 |
| 개선 | **한 번에 하나만 바꾼다.** 모델 크기와 입력 해상도를 같이 바꾸면 무엇 때문인지 모른다 |
| 재현 | 시드·서브셋 목록·설정을 커밋한다. 같은 명령으로 같은 숫자가 나와야 한다 |

## 한 번의 실험 = 한 폴더

```
ml/runs/2026-10-05_e1_two-stage/
  config.json      모델·입력 크기·에폭·시드 등 전부
  metrics.json     zones.sweep() 결과
  report.md        무엇을 바꿨고 무엇이 달라졌는지 3~5줄
  predictions.csv  image_id,facility,y_true,score
```

`ml/runs/`는 `.gitignore` 대상이다. 저장소에는 `report.md`의 내용을 실험 이슈에 옮겨 적는다.

## 실험 이슈에 남길 것

```markdown
## 가설
검출과 판정을 나누면 미준수 재현율이 오른다.

## 바꾼 것 (하나만)
1단계 통합 검출 → 2단계(검출 후 크롭 분류)

## 결과
| | 미준수 재현율 | 확인 필요 비율 | 추론 시간 |
|---|---|---|---|
| 1단계 | 0.81 | 12% | 21ms |
| 2단계 | 0.88 | 9% | 34ms |

## 판단
2단계 채택. 추론 시간이 1.6배지만 현장은 실시간이 아니라 촬영 후 판정이라 감당된다.

## 진 쪽의 약점도 기록
1단계는 작은 결함(부식)에서 특히 약했다.
```

**진 쪽을 지우지 않는다.** "B랑 C는 왜 안 됐습니까"에 답할 재료다.

## 숫자를 말할 때

- 정확도 하나로 말하지 않는다. **놓침률·확인 필요 비율·오경보율**을 함께 낸다
- 추정치와 실측치를 구분해 적는다. 추정이면 "추정"이라고 쓴다
- 개선 폭이 작으면 우연일 수 있다는 것도 같이 적는다
- 비교 대상 없는 숫자는 의미가 없다. "20% 줄었다"는 **무엇과 비교했는지**까지 적어야 한다

## E4(서류 시간)만의 규칙

사람이 들어가는 측정이라 조건을 흔들면 안 된다.

- 같은 사람이 두 방식을 모두 수행한다
- 순서 효과를 없애려고 시나리오를 바꿔 교차한다 (종이 → 앱, 다음 회차는 앱 → 종이)
- 시간은 앱이 자동 기록하고, 종이 방식은 스톱워치로 잰다
- 절대 시간보다 **같은 사람 기준 배수**를 핵심 지표로 삼는다
- 측정자가 개발자 본인이라는 한계를 결과에 함께 적는다
