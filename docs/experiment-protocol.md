# 실험 수행 규칙

교안의 평가 기준은 "무엇을 만들었나"가 아니라 **"왜 그 방법을 골랐고 성능을 어떻게 점수화했나"**다. 실험을 돌리는 방식이 곧 결과물이므로 규칙을 정해 둔다.

## 다섯 단계

| 단계 | 규칙 |
|------|------|
| 정의 | 무엇을 좋게 만들 것인지 한 문장으로 먼저 적는다. 여기서는 **놓침률 상한을 지키며 재검률 최소화** |
| 측정 | 지표 계산 코드를 먼저 만든다 (`ml/hancut/eval/zones.py`). 재지 못하면 좋아진 걸 증명할 수 없다 |
| 정답지 | 어디서 왔는지 기록한다 — 데이터셋 라벨인지, 내가 직접 입력한 것인지 |
| 개선 | **한 번에 하나만 바꾼다.** 모델 크기와 입력 해상도를 같이 바꾸면 무엇 때문인지 모른다 |
| 재현 | 시드·설정·확정 임계값을 커밋한다. 같은 명령으로 같은 숫자가 나와야 한다 |

## 한 번의 실험 = 한 폴더

```
ml/runs/2026-10-10_e1_max-vs-calibrated/
  config.json      모델·입력 크기·에폭·시드 등 전부
  metrics.json     zones.sweep() 결과
  report.md        무엇을 바꿨고 무엇이 달라졌는지 3~5줄
  predictions.csv  image_id,item,y_true,score  (사진 × 품목마다 한 행)
```

`ml/runs/`는 `.gitignore` 대상이다. 저장소에는 `report.md`의 내용을 실험 이슈에 옮겨 적는다.

## 실험 이슈에 남길 것

```markdown
## 가설
박스 점수의 최댓값 대신 보정된 집계를 쓰면, 같은 놓침률 1% 에서 재검률이 줄어든다.

## 바꾼 것 (하나만)
이미지 점수 = 박스 점수 최댓값 → 온도 보정 후 최댓값

## 결과
| | 놓침률 상한 | 재검률 | 오경보율 | 양성 n |
|---|---|---|---|---|
| 최댓값 | 1% | __% | __% | 22,250 |
| 보정 후 | 1% | __% | __% | 22,250 |

양성 n 은 시험셋의 (사진, 품목) 양성 합계다. easy 9,482 + hard 7,763 + hidden 5,005.

## 판단
어느 쪽을 채택했는지, 차이가 표본 변동보다 큰지를 적는다.

## 진 쪽의 약점도 기록
최댓값 방식은 hard(품목 여러 개가 겹친 사진)에서 특히 재검이 많았다.
```

**진 쪽을 지우지 않는다.** "B랑 C는 왜 안 됐습니까"에 답할 재료다.

## 숫자를 말할 때

- 정확도나 mAP 하나로 말하지 않는다. **놓침률·재검률·오경보율·자동 처리율**을 분모와 함께 낸다
- 놓침률 상한은 측정 가능한 범위(5·2·1%)에서만 주장한다. 0.1% 는 어느 품목도 검증할 수 없다(D12)
- 추정치와 실측치를 구분해 적는다. 추정이면 "추정"이라고 쓴다
- 개선 폭이 작으면 우연일 수 있다는 것도 같이 적는다
- 비교 대상 없는 숫자는 의미가 없다. "20% 줄었다"는 **무엇과 비교했는지**까지 적어야 한다

## E2 평가 CLI (#9)

저장소 루트에서 실행한다. CSV 필수 열은 `image_id,item,y_true,score`이며,
`y_true=1`이 해당 품목 있음, `score`는 0~1의 `p(품목 있음)`이다.

**평가 단위는 사진 × 품목이다(#6).** 사진 한 장이 품목 수만큼 행을 가지며, 고유 키는 `(image_id, item)` 이다.
같은 사진이 여러 행에 나오는 것은 정상이다. 같은 `(image_id, item)` 이 두 번 나오면 오류다.
`build_index.py` 가 만드는 인덱스와 열 이름·단위가 같다. 품목명 `default`는 예약어다.

```bash
.venv/bin/python ml/scripts/evaluate.py ml/runs/validation.csv \
  --output-dir ml/runs/e2-validation \
  --miss-caps 0.01 0.02 0.05 --select-cap 0.01 --false-alarm-cap 0.05 \
  --test-csv ml/runs/test.csv
```

- `report.md`: 전체/품목별 E2 표. 보정 결과와 독립 시험 결과를 구분한다.
- `metrics.json`: 표본 수, 지표, 선택 상한, 입력 파일 SHA256.
- `thresholds.json`: 서버가 읽는 default + 품목별 low/high. 반올림하지 않는다.
- `--test-csv`는 선택 사항이다. 없으면 일반화 성능 미평가라고 보고한다.
- 시험셋에서는 품목별 고정 임계값을 사용하며 처음 보는 품목은 default로 평가한다.
- 검증/시험 사이 이미지 ID 중복(누수), 같은 `(image_id, item)` 중복, 잘못된 CSV, 단일 클래스 보정, 기존 출력 덮어쓰기는 오류로 종료한다.
- 같은 가방을 다른 ID로 찍은 누수까지 검출하지는 못한다. PIDray 공식 split 은 `build_index.py` 로 파일명 기준 누수가 없음을 확인했다.
- `high<=1`이므로 음성(품목 없음) 점수가 1인 행이 많으면 오경보 상한을 만족하지 못한다. 이 경우 내보내기를 중단한다.
- 임계값 선택 표본에서의 상한 충족은 실서비스 성능 보장이 아니다. 시험셋에서 상한을 넘으면 결과를 그대로 보고한다.
- 표에 표시한 임계값은 가독성을 위해 반올림한다. 서버에는 반드시 JSON을 전달한다.

후보별 전체 재탐색을 정렬/이진 탐색으로 바꿔 대용량 입력에서 O(n²) 계산을 피했다.
후보와 경계 규칙은 유지하며 기존 방식과의 일치 테스트로 검증한다.
