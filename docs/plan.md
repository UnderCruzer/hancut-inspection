# 실행 계획

## 주제

**소방시설 자체점검 업무의 AI 전환 — 사진 기반 준수 판정과 점검표 자동 작성**

사용자: 소방시설관리업체 점검원, 아파트·상가 관리사무소 소방안전관리자

## 바꾸는 업무

| 항목 | Before | After |
|------|--------|-------|
| 현장 확인 | 종이 점검표에 눈으로 체크 | 찍으면 종류·준수 여부·사유 판정 |
| 증빙 사진 | 폴더에 따로 보관, 나중에 매칭 | 판정과 사진이 항목에 자동 연결 |
| 소화기 연한 | 제조연월 읽고 직접 계산 | 라벨 판독 → 10년 경과 자동 판정 |
| 서류 작성 | 사무실에서 한글·엑셀로 옮겨 적기 | 점검표·조치사항 문장 초안 생성 |

법정 절차: 점검 종료일부터 10일 이내 점검표 첨부 보고서 → 관계인, 15일 이내 관계인 → 소방본부장·소방서장 (소방시설 설치 및 관리에 관한 법률 시행규칙 제23조). 분말소화기 내용연수 10년.

## AI 구성

1. **시설 인식 (Vision)** — 24종 중 무엇인지 검출
2. **준수 판정 (Vision)** — 준수 / 미준수 + 사유
3. **연한 확인 (OCR)** — 소화기 제조연월 → 10년 경과 여부
4. **점검표 초안 (LLM)** — 판정 결과만 입력. **사진은 주지 않는다**

## 판정 3구간

| 구간 | 조건 | 처리 |
|------|------|------|
| 자동 · 준수 | `p_미준수 < low` | 확인 없이 반영 — 여기 섞인 미준수가 곧 '놓침' |
| 확인 필요 | `low ≤ p < high` | 점검원이 직접 판단 |
| 자동 · 미준수 | `p ≥ high` | 사유와 함께 반영, 사진으로 빠르게 확인 |

`low`는 **놓침률 상한**(1·3·5%)을 지키는 가장 큰 값, `high`는 오경보 상한을 지키는 가장 작은 값으로 정한다.

## 범위 조정 (1인)

4인 기준 계획에서 아래를 덜어냈다. 줄인 것을 숨기지 않고 발표에서 밝힌다.

| 항목 | 4인 계획 | 1인 계획 |
|------|----------|----------|
| E5 점검표 초안(LLM) · E6 연한 판독(OCR) | 둘 다 | **하나만** (W13) |
| E7 정정 재학습 | 여유 시 수행 | 수행하지 않음 — 설계만 문서화 |
| 앱 오프라인 동기화 | 포함 | 제외 — 온라인 전제 |
| 점검표 PDF 출력 | 포함 | 제외 — 화면·CSV까지 |
| 시설 범위 | 8종 → 24종 확장 | **8종 고정** |

줄이지 않는 것: **E1–E4와 점검 앱**. 이 넷이 "무엇을 골랐고, 얼마나 안전하며, 얼마나 줄였는가"를 만든다.

## 혼자 할 때의 운영 규칙

- 이슈 → 브랜치 → PR → 머지. 리뷰어가 없어도 PR을 거친다 — 변경 이유가 기록으로 남는다.
- 작업 추적은 GitHub Projects 보드 하나로. 주차별 컬럼을 쓴다.
- 매주 한 줄씩 `docs/progress.md`에 기록한다. 중간·기말 점검 자료가 여기서 나온다.
