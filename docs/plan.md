# 한컷점검 — 보안검색 판독의 위임 학습 (1인)

2026-09-24. 범위 전환 #12, 과제 재정의 #16. 이전 계획은 `docs/archive-weqaa/plan.md`.

## 한 문장

보안검색 X-ray 사진에서, **모델이 언제 스스로 판정하고 언제 판독관에게 넘길지를 함께 학습한다.**

## 무엇이 기여인가

탐지도 포화, 분류도 포화다. PIDray 의 다중 라벨 분류와 검출은 이미 논문의 공식 벤치마크 과제다.
**새 탐지기도, 새 손실 함수도 만들지 않는다.**

만드는 것은 그 위에 얹히는 **위임 정책**이다. 기존 방식은 임계값을 스윕해서 자르는 것이고,
Learning to Defer 는 사람의 정확도와 재검 비용을 손실 안에 넣어 **예측기와 위임기를 함께 학습**한다.

방법론은 확립돼 있다 — Mozannar & Sontag 2020(softmax surrogate), Verma & Nalisnick 2022(OvA),
Mao 외 2024(H-consistency). 가져다 쓴다.
비어 있는 것은 **X-ray 보안검색에의 적용**이다. 선택적 예측·기권을 이 도메인에 결합한 연구는 확인되지 않았다.

## 세 가지 질문

1. 같은 **위임 예산**(사람에게 넘기는 비율)에서, 학습된 위임기가 고정 임계값보다 놓침을 줄이는가
2. **판독관을 어떻게 가정하느냐가 위임 규칙을 얼마나 바꾸는가** — 정확도 80% vs 90%, 난이도 조건부 vs 균일
3. 장비가 바뀌면 위임기를 다시 학습해야 하는가

2번이 이 과제에서 가장 흥미롭고, 실무에서 가장 먼저 부딪히는 질문이다.
"판독관이 이 정도 실력이다"라는 가정 하나가 시스템 설계를 어디까지 흔드는지를 본다.

## 판독관 시뮬레이션 — 핵심 설계이자 최대 한계

실제 판독관의 사진별 응답 데이터가 없다. 시뮬레이션한다. **이 사실을 발표에서 먼저 밝힌다.**

다만 균일 노이즈를 쓰지 않는다. PIDray 는 테스트셋을 난이도로 나눠 제공하므로
**난이도 조건부 정확도**를 가진 전문가를 만들 수 있다.

| 난이도 | 내용 | 시뮬레이션 판독관 |
|---|---|---|
| easy (24,758) | 품목 하나 | 높은 정확도 |
| hard (9,746) | 품목 여러 개 | 중간 |
| hidden (13,069) | 고의로 은닉 | 낮음 |

전체 정확도는 EU JRC 의 80~90% 에 맞춘다. 난이도별 배분은 실험 변수로 두고 E4 에서 흔든다.

**모델과 사람이 서로 다른 것을 틀릴 때에만 위임이 이득이다.** 이 설정을 바꿔가며 그 조건을 찾는 것이
E4 의 목적이고, 시뮬레이션이라는 한계를 실험 축으로 바꾸는 방법이다.

## 기준선

| 기준선 | 내용 |
|---|---|
| 항상 모델 | 위임 없음 |
| 항상 사람 | 자동화 없음 |
| **고정 임계값 3구간** | **기존 `ml/hancut/eval/zones.py`. 이걸 이겨야 한다** |
| 신뢰도 기반 기권 | 예측기 신뢰도만 보고 넘김 (selective prediction) |
| 학습된 위임기 | L2D |

같은 위임 예산에서 **시스템 전체 놓침률**을 비교한다. 예측기 단독 성능이 아니라 사람+모델 합산이 지표다.

## 실험

| 코드 | 질문 | 필수 |
|---|---|---|
| E1 | 박스 점수를 품목별 이미지 점수로 어떻게 바꾸나 | 필수 |
| E2 | 고정 임계값 3구간 기준선 (`zones.py`) | 필수 |
| E3 | 학습된 위임기가 E2 를 이기는가. 같은 위임 예산에서 비교 | **필수 · 핵심** |
| E4 | 판독관 가정을 바꾸면 위임 규칙이 어떻게 달라지나 | **필수 · 가장 흥미로움** |
| E5 | 장비가 바뀌면 위임기를 다시 학습해야 하나 | 선택 |
| E6 | 난이도별로 위임 예산을 다르게 주면 나아지나 | 선택 |

**E5 는 장비 메타데이터가 실제로 파일에 있어야 성립한다.** #14 에서 가장 먼저 확인한다. 없으면 E6 을 한다.

## 완료 기준

위임 예산별 시스템 놓침률 곡선을 다섯 기준선과 함께 보고한다. 분모를 항상 같이 적는다.
판독관 가정을 최소 네 가지로 바꿔 E3 의 결론이 뒤집히는 지점이 있는지 밝힌다.
뒤집힌다면 그것도 결과다 — **"이 방법이 이득인 조건은 여기까지"** 가 결론이 된다.

## 하지 않을 주장

**새 탐지기나 새 손실 함수를 만들었다고 말하지 않는다.** 기존 방법을 가져다 쓴다.

**시뮬레이션 판독관을 실제 판독관이라고 말하지 않는다.** 실제 검증에는 사람 실험이 필요하고 이 프로젝트 범위 밖이다.

**실제 공항 운영에 쓸 수 있다고 말하지 않는다.** TSA/ECAC 의 요구 수치는 비공개이고, 공개 벤치마크 위의 분석이다.

## 현재 구현

`ml/hancut/eval/zones.py`(3구간 판정·임계값 탐색)는 **버리지 않는다. E2 기준선이다.**
`eval/cli.py`, `data/subset.py`, 판정 API 골격, Flutter 앱 골격도 그대로 쓴다.
새로 필요한 것은 판독관 시뮬레이터, L2D 손실, 위임 예산별 비교 스크립트다.

코드의 `facility`·`compliant` 식별자는 소방시설 시절 이름이다. #13 에서 정리한다.
데이터·가중치·키는 Git 에 넣지 않는다.
